## 🏛️ 一、 核心定位与研究范式

系统扮演一名**“中立、严苛、只认真实审计账目与法定披露的金融事实查验员（Fact-Checker）”**，遵循【因果解构 + 多源对账 + 审慎证据链 + 波普尔证伪主义】范式：
- **审慎归因原则（证据支持到哪，结论走到哪）**：
  若取得收入增速高于销量增速及官方调价公文，系统**仅能判断“与价格/渠道驱动解释一致”或“部分支持”**；在缺乏经审计的分部毛利贡献拆分数据前，**严禁仅凭量价增速差就越级确认其对利润增长的主要贡献**；
- **反对证据精准对应**：每条反对证据必须精确绑定其削弱的具体子假设维度（如现金流背离削弱的是“利润真实变现质量”，而非直接推翻“过去提价行为”）；普通行业风险提示不得直接判定为反证；
- **自下而上的强 ID 引用闭环**：
  `raw_ref_id` (真实原始报文) ➔ `fact_id` (抽取真实原子事实) ➔ `computation_id` (确定性计算) ➔ `evidence_id` (证据卡片) ➔ `sub_id` (子假设判定) ➔ `FinalReport` (结构化报告)。
- **严禁虚假数据兜底**：系统 100% 使用真实上游接口数据，**严禁硬编码预设数字、结论或置信度**，严禁用 Mock 数据兜底冒充真实上游返回。

## 🚀 五、 快速启动与使用指南

### 1. 环境准备
项目需要 Python 3.10+。项目路径已做好兼容 Windows 中文与空格路径的处理。

```powershell
# 1. 克隆/打开项目根目录
cd "D:\My Data\桌面\同花顺笔试"

# 2. 创建并激活虚拟环境
python -m venv .venv
.\.venv\Scripts\Activate.ps1

# 3. 安装依赖锁定
pip install -r requirements.txt
```

### 2. 环境变量配置
复制根目录模板 `.env.example` 为 `.env`：
```ini
fuyao_Key=your_fuyao_api_key_here
IFinD_MCP=your_ifind_mcp_bearer_token_here
Base_url=https://api.siliconflow.cn/v1
Model=deepseek-ai/DeepSeek-V4.1-Flash
API_Key=your_siliconflow_api_key_here
```
> **安全说明**：`.env` 与真实密钥已被 `.gitignore` 排除，严禁提交到代码仓库。

### 3. 一键启动服务
可以直接双击运行根目录 `run.bat`，或在命令行执行：
```powershell
.\.venv\Scripts\uvicorn.exe fin_verifier.main:app --host 0.0.0.0 --port 8000 --reload
```
- **Web 工作台界面**：`http://127.0.0.1:8000`
- **Swagger API 文档**：`http://127.0.0.1:8000/docs`

### 4. 运行自动化测试套件
```powershell
.\.venv\Scripts\pytest.exe tests/ -v
```
覆盖 24 项单元测试、边界测试、防伪门禁测试与全部 9 个 API 路由集成测试。

## 📡 六、 9 个核心 REST API 契约表

| 方法 | 路径 | 职责 |
| :--- | :--- | :--- |
| `GET` | `/api/demos` | 载入典型命题模板（不含硬编码答案） |
| `GET` | `/api/tickers/search` | 标的实时查询与消歧候选 |
| `POST` | `/api/clarify` | Step 0 命题澄清，返回规范命题、合规说明与建议维度 |
| `POST` | `/api/verify` | 异步创建任务并启动流水线，毫秒级即时响应 `task_id` |
| `GET` | `/api/tasks/{task_id}` | 查询任务实时状态、全量事实、证据卡片与研报 |
| `GET` | `/api/tasks` | 历史任务列表与收藏筛选 |
| `PATCH` | `/api/tasks/{task_id}/star` | 设置任务收藏状态与自定义标签（标签自动去重） |
| `GET` | `/api/compare` | 基于已存任务并排组装双任务对比视图（不额外调 LLM） |
| `POST` | `/api/tasks/{task_id}/inquire` | 基于当前任务已存事实回答用户追问并持久化 |

## ⚠️ 七、 边界条件与未做事项说明

1. **客观数据缺口诚实披露**：未审计公开口径（如“第三方烟酒店与经销商实际未开箱库存”）属于非上市公司披露口径，系统如实标记为 `UNVERIFIABLE` 并保留缺口记录，**坚决不调用 LLM 记忆幻觉或编造非公开数据**。
2. **轻量流水线架构**：采用单 Agent 阶段状态机流水线，不引入重型多 Agent 协商框架、向量数据库或额外调度平台，完全基于单文件原子替换写入（`.tmp` 写入后 `os.replace` 原子替换）保证并发安全与持久化回溯。
3. **单公司验证工作台定位**：项目聚焦于单命题、单公司深度证伪对账，打通贵州茅台典型案例，不承诺全市场通用投研平台能力。
